# 编译器整体架构

## 编译器是什么

编译器是一种将**高级语言源代码**转换为**目标代码**（机器码或汇编）的程序。其核心任务是让程序员用人类易读的语言编写程序，而编译器负责翻译成计算机能执行的指令。

```
源代码 (C 语言)
  ┌──────────────────────────────────────┐
  │           编译器 (Compiler)           │
  └──────────────────────────────────────┘
           │
           ▼
目标代码 (RISC-V 汇编 / 机器码)
```

---

## 编译器的主要阶段

一个基本的编译器通常分为**前端**和**后端**两大部分：

```
源代码
  │
  ▼
┌─────────────┐
│   词法分析   │  将源代码分割成一个个 Token（标记）
└─────────────┘
  │
  ▼
┌─────────────┐
│   语法分析   │  将 Token 组合成 AST（抽象语法树）
└─────────────┘
  │
  ▼
┌─────────────┐
│  语义分析   │  类型检查、作用域检查等
└─────────────┘   ← 本项目的 AST 生成阶段（GenIR）承担了部分语义分析工作
  │
  ▼
┌─────────────┐
│  中间表示    │  生成平台无关的 IR（Koopa IR）
│   (IR)       │
└─────────────┘
  │
  ▼
┌─────────────┐
│   优化       │  （本项目暂未实现）
└─────────────┘
  │
  ▼
┌─────────────┐
│  目标代码    │  将 IR 转换为特定架构的汇编
│   生成       │  ← RISC-V 后端
└─────────────┘
  │
  ▼
汇编/机器码
```

## 本项目的编译器结构

本项目是一个基于 **SysY 语言**（北大MiniC教学语言）的编译器，从前端到后端包含以下模块：

```
Flex/Bison (外部工具)
  └── parser.y / lexer.l
       │
       ▼  (自动生成)
  yyparse() → AST
       │
       ▼
ast.h / ast.cpp
  ├── AST 节点定义
  └── AST → IR 生成 (GenIR)
       │
       ▼
ir.h
  ├── 指令类 (AllocInst, StoreInst, LoadInst, ...)
  ├── 基本块 (BasicBlock)
  ├── 函数 (Function)
  └── 程序 (Program)
       │
       ▼  (Koopa 库)
  Koopa IR 字符串
       │
       ▼  (Koopa 库解析)
  koopa_raw_program_t (Raw IR)
       │
       ▼
riscv.h / riscv.cpp
  └── RISC-V 汇编生成
       │
       ▼
RISC-V 汇编 (.s 文件)
```

## 文件对应关系

| 文件 | 职责 | 对应编译器阶段 |
|------|------|--------------|
| Flex/Bison (parser.y) | 词法+语法分析，生成 AST | 前端 |
| **ast.h** | 定义所有 AST 节点类和符号表 | 前端/语义分析 |
| **ast.cpp** | AST → Koopa IR 的转换实现 | 中端 |
| **ir.h** | 定义 Koopa IR 的数据结构（指令、基本块、函数等） | 中端 |
| **riscv.cpp** | 将 Koopa IR 转换为 RISC-V 汇编 | 后端 |
| **riscv.h** | RISC-V 生成器的接口定义 | 后端 |
| **main.cpp** | 串联各阶段，处理输入输出 | 主程序 |

## 编译流程详解

### 第一步：词法+语法分析

由 Flex 和 Bison 自动生成的 `yyparse()` 函数完成：
- **Flex (lexer.l)**：将源代码字符串分割成 Token 序列（如 `INT`、`IDENT`、`NUM`、`IF`、`+`、`-` 等）
- **Bison (parser.y)**：根据语法规则将 Token 序列组装成 AST

### 第二步：AST 生成

`CompUnitAST::GenIR()` 从根节点出发，递归调用每个子节点的 `GenIR()`：
- 每个 AST 节点知道如何**将自己翻译成 IR 指令**
- 同时通过 **SymbolTable** 管理变量/常量的作用域
- 生成的结果是**平台无关的 Koopa IR**

### 第三步：Koopa IR 输出

`Program::Dump()` 将 IR 数据结构序列化为 Koopa IR 文本格式（如 `out.koopa`）。

### 第四步：Koopa 库解析

`koopa_parse_from_string()` 将 Koopa IR 文本解析回 Koopa 库的结构，然后 `koopa_build_raw_program()` 转换为平面化的 Raw IR，供后端遍历。

### 第五步：RISC-V 汇编生成

`RiscVGenerator::Generate()` 以**访问者模式**遍历 Raw IR：
- 遇到 `alloc` → 在栈上分配空间
- 遇到 `store` → 用 `sw` 指令写栈
- 遇到 `load` → 用 `lw` 指令读栈
- 遇到 `add/mul/...` → 生成对应的 RISC-V 算术指令
- 遇到 `branch/jump` → 生成 `bnez/j` 等跳转指令

## 核心数据结构

### AST（抽象语法树）

AST 是源代码的**树形结构表示**：
- **根节点**是 `CompUnitAST`（编译单元）
- 每个**内部节点**是一种语法结构（如函数定义、语句、表达式）
- 每个**叶子节点**是基本元素（如变量名、数字、运算符）

### IR（中间表示）

IR 是介于源代码和目标码之间的桥梁：
- **基于指令**：由 `alloc`、`store`、`load`、`add` 等指令组成
- **SSA 形式**：每个值有唯一 ID（`%0`、`%1` 等）
- **有控制流**：通过 `br`（条件分支）和 `jump`（无条件跳转）组织基本块

### SymbolTable（符号表）

符号表管理**变量的作用域信息**：
- 记录每个变量/常量的**名字 → 地址/值**的映射
- 通过 **parent 指针**形成作用域链，实现嵌套作用域

## 编译器的挑战

| 挑战 | 描述 | 本项目的解决方案 |
|------|------|---------------|
| 寄存器分配 | 无限临时值 vs 有限寄存器 | 全部栈分配（简单策略） |
| 变量作用域 | 嵌套作用域中内层变量遮蔽外层 | SymbolTable 父指针链 |
| 控制流 | if/while 等结构需要跳转 | 基本块 + g_end_block_stack |
| 循环回边 | while 循环体末尾需要跳回条件 | WhileStmtAST 修复循环扫描 |
| break/continue | 需要知道跳转目标 | g_loop_stack 维护循环上下文 |
